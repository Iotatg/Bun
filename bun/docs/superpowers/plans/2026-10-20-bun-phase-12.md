# Phase 12 — The AI Stack (`bun:ai`)

Date: 2026-10-20
Status: In progress.

## Objective

Give a Bun program the whole model loop without leaving the language:
build a model, train it, save it, load it, run it.

The research behind this phase is in
`docs/superpowers/research/2026-10-20-bun-ai-stack.md`. The short
version: `bun:tensor` already owns the tensor and the gradient, and what
is missing is the rows above them — the layer, the model, the format, the
loop, the token.

The rule of the phase: **a model is data**. A model is a dict with a
`"kind"` marker, its parameters are tensors, and the on-disk shape of a
model is the on-disk shape of its parts, so a binary format can be added
later without a redesign.

## 1. The layers

A layer is a module function, like every other function of the other
stacks.

| Function | Shape in | Shape out |
|----------|---------|-----------|
| `linear(x, w, b)` | `[batch, in]` | `[batch, out]` |
| `relu(x)` | any | same |
| `gelu(x)` | any | same |
| `layernorm(x, gamma, beta, eps)` | `[batch, features]` | same |
| `embedding(table, ids)` | `[vocab, dim]`, ids `[n]` | `[n, dim]` |

The forward pass of a layer that has weights records its backward rule on
the tape of `bun:tensor`, so a model built out of these layers trains
without a second implementation of the gradient.

`gelu` uses the exact formula `0.5 * x * (1 + erf(x / sqrt(2)))`, so the
value is the same on every machine. The `erf` comes from `ffi_load("math")`,
the same source the tensor stack uses.

## 2. The model and the format

A model is a dict:

```
{
  "kind":    "model",
  "name":    "mlp",
  "params":  { "w0": <tensor>, "b0": <tensor> },
  "layers":  [ { "op": "linear", "w": "w0", "b": "b0" }, ... ],
  "seed":    1234
}
```

A layer in the list names the operation and the *names* of its
parameters, so a model file never repeats the weights.

- `model_to_json(model)` — the JSON text of the model, with the tensors
  written in their own shape.
- `model_from_json(text)` — the model back.
- `save_model(model, path)` / `load_model(path)` — the file pair.
- `param_count(model)` — the number of parameters.

The JSON is written by `json_stringify`, so the key order is the sorted
order of the runtime, and a model file is byte-for-byte the same for the
same model.

## 3. The losses and the optimizers

- `mse_loss(pred, target)` — the mean squared error, as a tensor with one
  element.
- `cross_entropy(logits, labels)` — the labels are a list of integers;
  the loss is `log-sum-exp(logits) - logits[label]`, which is stable
  when a logit is large.
- `binary_cross_entropy(pred, target)`.
- `sgd(params, grads, rate)` — the update in place, with a weight decay
  of zero by default.
- `adam_step(params, grads, state, rate, step)` — the Adam update of
  `bun:tensor`, with the state kept in the model.

Every loss returns a tensor with one element, so `backward()` of
`bun:tensor` accepts it directly.

## 4. The training loop

`train(model, x, y, options)` where the options are:

| Key | Meaning |
|-----|---------|
| `epochs` | the number of passes over the data |
| `batch_size` | the size of a step |
| `rate` | the learning rate |
| `loss` | `"mse"` or `"cross_entropy"` |
| `seed` | the seed of the shuffling |
| `optimizer` | `"sgd"` or `"adam"` |

The loop returns a history dict: `{"loss": [...], "epoch": [...]}`. The
samples are shuffled with the seeded generator before every epoch, so the
order is the same for the same seed.

## 5. The tokenizer and the sampler

- `word_tokenizer(text)` — a dict with `"vocab"` and `"ids"`.
- `char_tokenizer(text)` — the same, one character per token.
- `encode(tokenizer, text)` — the ids of a text.
- `decode(tokenizer, ids)` — the text of the ids.
- `sample(probs, temperature, seed)` — a deterministic draw from a
  distribution. The generator is a linear congruential generator, so the
  draw is a function of the seed and the index and never of the clock.

## 6. The language model

`train_language_model(tokenizer, hidden, rate, epochs)` builds a word
level model with an embedding, a hidden layer with `tanh`, and a
softmax over the vocabulary, and trains it on the text of the tokenizer.
`generate(model, tokenizer, length, seed)` samples from the model.

The model is small on purpose: the point is the loop, not the size.

## 7. The tests

`tests/test_ai.py` holds the four acceptance criteria of the research
document:

| Test | What it proves |
|------|----------------|
| the gradient of a linear layer | the number, checked against a value computed by hand |
| the loss of a training run | it goes down, from a value above to a value below |
| two runs with the same seed | the same list of losses, exactly |
| the round trip through JSON | the same answer after saving and loading |

## 8. What is deferred

- **Attention and the transformer.** The matrix multiply is interpreted,
  so the attention matrix is too slow to train. The recurrent family
  teaches the same loop.
- **A binary format.** safetensors and GGUF need a binary writer. The
  JSON shape is the same shape, so the converter is a walk, not a
  redesign.
- **A subword tokenizer.** BPE needs a trained vocabulary and a merge
  table. The interface (`encode`/`decode`) is fixed, so it drops in.
- **A fused kernel or a compiled backend.** The natural host for it is
  the Phase 11 C backend, which is not written yet.
- **A GPU.** The runtime has no GPU access.

## 9. What came after

The phase added the stack, the tests, and the documentation.

The tensor stack grew three exports for the layers of this stack:
`record_rule`, `take_grad` and `accumulate_grad`. A layer that lives
outside `bun:tensor` records its rule on the one tape, so a model made
of layers of two stacks trains with one backward pass.

The documentation registry was not changed: it holds the builtins of the
language, and the functions of a native module are documented in the
module itself, as the other three stacks are.
