# Bun Phase 5 Implementation Plan: Self-Hosted Type Checker

**Goal:** Port `bun/checker.py` and the `bun/types.py` rules to Bun, run the
checker from `selfhost/main.bun` for `--front-end bun`, and prove
message-for-message parity against the Python checker.

**Architecture:** `selfhost/checker.bun` walks Phase 4 AST dicts, dispatching on
`kind`. The driver receives `[path, mode, check_flag, base_dir]`; for `run` it
checks before compiling. Four bridge builtins in `bun/selfhost.py` cover host
integration: `type_error` raises `BunTypeError`, `type_of` classifies literal
values, `module_path` resolves imports, and `read_module` reads module source
with the Python loader's messages. The Python pipeline still lexes and
parses the entry file for static lex/parse errors but no longer runs the Python
checker on the Bun front-end path.

**Tech Stack:** Python >= 3.8 standard library only; Bun (no classes, no
`break`/`continue`, no `isinstance`); pytest.

## Global Constraints

- Python >= 3.8, standard library only.
- Every language-level error is a `BunError` subclass.
- `LexError` and `ParseError` stay Python-raised, positioned, and
  non-catchable on every front end.
- `BunTypeError` from the Bun checker carries the same message, line, and
  column as `bun/checker.py`.
- No code comments in committed code.

## File Structure

- Create `selfhost/checker.bun` — types, builtin signatures, scoped walk, module
  export collection, `check_program(program, base_dir)`.
- Modify `selfhost/main.bun` — import the checker; extend `args()`; add `check`
  mode; check before compile in `run` mode.
- Modify `bun/selfhost.py` — `type_error`, `type_of`, `module_path` builtins;
  `run_front_end` passes mode, flag, and base dir and no longer runs the Python
  checker.
- Modify `tests/test_selfhost.py` — corpus parity, error parity, import parity,
  and an unchecked-run test.
- Docs: `README.md`, `docs/superpowers/specs/2026-10-14-bun-language-design.md`,
  this phase's design spec.

---

### Task 1: Bun checker core

**Files:** Create `selfhost/checker.bun`.

- Port `TYPES`, `BUILTIN_SIGNATURES`, `is_known_type`, `is_assignable`.
- Port binding/scope helpers (`make_binding`, `make_fn_binding`,
  `param_types`, `copy_scope`) and state.
- Port statement dispatch: declarations, assignments, returns, blocks,
  branches, loops, expression statements, `try`/`catch`/`throw`.
- Port expression dispatch and calls: identifier lookup, literals via
  `type_of`, direct calls (arity, parameter types), builtin signatures.
- Port module export collection and cycle detection.

Reference: `bun/checker.py`, `bun/types.py`, `bun/modules.py`.

Verification: `python3 -m pytest tests/test_selfhost.py -q -k checker`.

### Task 2: Driver and bridge

**Files:** Modify `selfhost/main.bun`, `bun/selfhost.py`.

- Driver: `should_check = mode == "check" or flag == "1"`; run
  `check_program(program, base_dir)` before compiling; `check` mode prints
  nothing.
- Bridge: add `type_error`, `type_of`, `module_path`, `read_module`; extend
  `args()` to
  `[path, mode, "1"|"0", base_dir]`; keep the Python lex/parse pass for static
  lex/parse errors; remove the Python checker call for the Bun front end.

Verification:
`python3 -m bun --front-end bun examples/hello.bun` and
`python3 -m bun --front-end bun <type-error>.bun`.

### Task 3: Parity tests

**Files:** Modify `tests/test_selfhost.py`.

- `test_checker_parity_on_corpus` — Python and Bun checkers agree on every
  corpus file.
- `test_checker_error_parity` — representative `(msg, line, col)` cases.
- `test_checker_import_parity` — import success and failure modes.
- `test_bun_checker_runs_unchecked_program` — `--no-check` skips checking.

Verification: `python3 -m pytest tests/test_selfhost.py -q`.

### Task 4: Full regression and docs

- Run `python3 -m pytest tests/ -q`.
- Update the README front-end paragraph and roadmap; update the language design
  roadmap; add this phase's design spec.

Acceptance: all tests pass, no skips introduced, docs describe the new path.
