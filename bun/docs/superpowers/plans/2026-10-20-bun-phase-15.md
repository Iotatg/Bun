# Phase 15 — The Music Path of the Bot

Date: 2026-10-20
Status: done

## The goal

The reference application of the language is the Ankita Music Bot, and it
has to *play music*. The voice chat of a group needs the user side of the
protocol and the credentials of an account, so that part waits. The music
itself does not: the Bot API can carry a track as a voice message, and
that path needs nothing but the token of the bot.

## The shape of the work

| # | Item | What it is |
|---|------|------------|
| 1 | The upload | The runtime gains `http_post_multipart`, so a program can post a file |
| 2 | The voice | The client of Telegram gains `send_voice` and `send_audio` |
| 3 | The transcoder | The track becomes the Ogg/Opus file of a voice message |
| 4 | The playback | The play command downloads the track and sends it |
| 5 | The check | The tests of the upload, and the smoke test of the bot |
| 6 | The docs | The README, the requirements of the system |

## The rules

- The two programs of the system stay optional. The bot starts without
  them and says what it cannot do.
- The upload is a feature of the language, not a trick of the bot: a
  language with an HTTP client that cannot post a file is a language
  without half of the web.
- The parts of the upload are data: a list of dictionaries, a field with a
  `value` and a file with a `path`.

## The notes of the phase

- The message was sent for real: the bot sent the voice message of a
  track to the chat of the owner, and the answer of the API carried the
  id of the message.
- The formats of YouTube that need a signature cipher cannot be
  deciphered by the runtime, which has no JavaScript engine. The
  external downloader is the way around it, and the bot falls back to it
  when the format of a track is protected.
- The `http_post_multipart` builtin is in the table of the builtins of
  the runtime and of the self-hosted checker, so the two pipelines agree
  on it, and the documentation registry describes it.
- The tests of the voice path never touch the network: the client of
  Telegram is replaced by a stub that records the parts of the upload, so
  the test can say that the file goes to `sendVoice` with the caption and
  the duration of the track.
- The flag `VOICE_MESSAGE` is checked before the track is fetched, so the
  bot with the flag off never downloads anything.
