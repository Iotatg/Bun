Date: 2026-10-20

## The goal

The language is queryable, not just readable. The protocol of this phase
lets an assistant drive a *session* of the language: JSON-RPC 2.0 over the
standard input and the standard output, one object per line.

## The shape of the work

| # | Item | What it is |
|---|------|------------|

| 2 | The values | The conversion of a value of Bun into JSON, and back |

| 4 | The command | `bun repl --json`, and the flag of the REPL |
| 5 | The check | The tests of the protocol, over a pipe |
| 6 | The docs | The README, the compatibility reference, the spec |

## The rules

- The protocol never changes the language. It is a surface over the same
  front end, the same checker and the same machine.
- A value comes back as a value, and a failure comes back as a failure
  with the kind, the message, the line and the column.
- The session is the session of the REPL: the same scope, the same
  builtins, the same errors.
- The examples of the documentation are tested, like every other example.

## The notes of the phase

- The answer of a call is a value, not a text. `eval` of `1 + 1` gives the
  number `2`, and the text of the value is there as well, because a human
  reads the text.
- The errors keep the two channels of the language: the kind of the error
  is `lex`, `parse`, `type` or `runtime`, and the data of the error of the
  protocol carries the message, the line and the column.
- A line that is not JSON does not kill the session: it is answered with
  the parse error of the protocol, and the next call works.
- The names of the session are the names of the program. The builtins are
  not names of the session, they are names of the language.
- The protocol is a surface, not a second language: it uses the same front
  end, the same checker and the same machine as the REPL.
